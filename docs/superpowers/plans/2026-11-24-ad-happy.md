# AD-Happy 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个 Skill + CLI，用户给出 Altium 工程文件夹路径后，离线解析原理图与 PCB、自建网表、复用 kicad-happy 规则，产出中文 JSON/HTML 测评报告。

**Architecture:** Node 侧用 altiumts 0.0.95 解析 `.PrjPcb`/`.SchDoc`/`.PcbDoc`，自写连通性引擎重建原理图网表；Python 侧把数据装成 `AnalysisContext` 与 `footprints`，直接调用 kicad-happy 检测器。两端通过 `raw.json` 通信，kicad-happy 只读引用、零修改。

**Tech Stack:** Node ≥ 20（ES modules、`node --test`、内置 fetch）、altiumts 0.0.95、Python ≥ 3.10（pytest）、kicad-happy 6a91aaa。

**Spec:** `docs/2026-11-24-ad-happy-design.md`

## Global Constraints

- Node ≥ 20；altiumts 锁定 **exact 0.0.95**，不允许 `^`。
- Python ≥ 3.10；测试用 pytest。
- kicad-happy 通过环境变量 `KICAD_HAPPY_SCRIPTS` 定位，默认 `D:/Tools/kicad-happy/skills/kicad/scripts`；不复制、不修改。
- 坐标单位：altiumts 输出 mil，转 mm 必须乘 **0.0254**。
- PcbDoc 的 net index 0 是真实网络，不是「未连接」；适配层需 +1 偏移。
- 走线、过孔、区域必须先按铜层过滤（TOP/BOTTOM/内层），丝印与机械层不参与几何检查。
- 报告语言中文；规则 ID、字段名保留英文。
- 源工程只读；所有输出写到 `--out` 指定目录，默认 `%LOCALAPPDATA%\ad-happy\runs\<run-id>`。
- 不对空数组或缺失字段下「通过」结论，一律标 `not_evaluated`。

## Review Focus

1. **空工程、无 SchDoc、多块 PcbDoc** —— 一个只有 PcbDoc 或只有 PrjPcb 的文件夹，应给出明确状态而不是崩溃。测试落在 Task 2。
2. **引脚热点方向解码错误** —— `PINCONGLOMERATE` 低 2 位解错会让整个网表错位。测试落在 Task 5。
3. **单位换算错误** —— mil→mm 乘错 10 倍，几何问题全部失真。测试落在 Task 8。
4. **net 0 被当成未连接** —— 整条 SW 网络会被误报。测试落在 Task 8。
5. **铜层未过滤** —— 208 条走线里 168 条是丝印/机械层，会污染 DFM 与线宽。测试落在 Task 8。
